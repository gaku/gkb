# Decision: Build a CLI for the Agent Knowledge Base

**Date:** 2026-07-01  
**Status:** Decided

## Context

We want a simple markdown-based knowledge base for AI agents, similar to how Joplin serves humans. The knowledge base uses flat `.md` files with YAML frontmatter.

## Decision

Build a CLI as the primary interface for creating, searching, and managing knowledge base entries.

## Rationale

- Agents and scripts can invoke a CLI easily
- Humans can use the same CLI from the terminal
- Keeps the KB tooling separate from the storage format (plain markdown)
- A CLI enforces schema discipline on writes, which makes entries predictable for agents

## Open Questions

- Search strategy (grep vs. semantic/vector)
- Who can write — humans only, agents only, or both?

## Commands

```
gkb init                 # initialize kb_dir, create ~/.gkb config
gkb add <title>          # create a new entry
gkb show <slug>          # display an entry
gkb edit <slug>          # open entry in $EDITOR
gkb delete <slug>        # remove an entry
gkb list                 # list all entries
gkb search <query>       # full-text search
gkb search --tag <tag>   # filter by tag
gkb status               # show kb_dir, entry count, last modified
gkb rename <old_slug> <new_slug>  # rename an entry
```

**Entry IDs:** slugified title (e.g. `auth-strategy`), no numeric IDs.  
**Entry types:** none — freeform tags only.  
**`add` flow:** creates the file, deferred editor integration.

## Config

**`~/.gkb`** — TOML format. Go library: `github.com/BurntSushi/toml`.

```toml
kb_dir = "~/self/kb/"
```

## CLI Name

**`gkb`** (gaku's knowledge base). Personal, unique, no collision risk with existing tools.

## Language

**Go.** Single binary, fast startup (important for agent invocation), mature CLI ecosystem (`cobra`/`viper`), trivial cross-compilation.
